## B. Methodological gaps a reviewer would hit

| # | Issue | Sev. | Evidence | Concrete fix |
|---|---|---|---|---|
| B1 | **The retrieval half of H3 ("and that improves retrieval") probably cannot show an effect on either dataset.** E-VQA (MuKA) has one entity image per page. MMQA images are also single-entity (A6). A crop of the only depicted entity adds little over the whole-image node. MG²'s "w/o MNF" gain (RF:213) comes from a 5k KB with its own construction. | blocker for H3 as worded | M:86, M:148; RF:131, RF:289; MA:48 | Make **grounding coverage and precision the primary H3 outcome**, with retrieval secondary and reported honestly. Or add a multi-entity source: official E-VQA KB section images (`image_section_indices`, RF:128), or a WebQA slice. |
| B2 | **H3 confounds *which* entities with *how* SAM3 is prompted.** Type-guided prompts a type noun phrase ("plant"). The MG²-style arm prompts entity names. The NER-label arm on *LLM* entities needs a spaCy label per LLM entity, which is undefined (run spaCy on the bare string? match spans in the passage?). The "all entities" arm needs a noun phrase for non-visual types, also undefined. | high | M:41, M:86; MA:42-43; MG2:578-586 | Fix the prompt form across arms: every arm uses its entity's type→noun phrase, and arms differ only in the selection rule. Define the NER labels of an LLM entity as the label of the spaCy span (from the same passage) that matches the entity string, with "no match" as unlabelled. Optionally add MG²'s literal name-prompt as an extra arm. |
| B3 | **Crop→entity assignment is ambiguous.** Several visual-typed entities in a passage can share one noun phrase ("animal"). M:41 says "link to the matching entity", but which one? A6 says "the entity that owns the image's passage", but entities are not owned by passages. | high | M:41; MA:43 | Specify: link a crop to the page's title entity if it has that type. Otherwise link it to all same-type entities, with weight 1/k (as MG² does with a set map, MG2:609-611). Or score crop vs entity name in CLIP text space and take the argmax. Report which rule is used. |
| B4 | **Pre-filter candidates may have no node to link to.** C7 holds (see C3 below), but entity nodes are created only from facts that survive filtering and conflict resolution (MGR:831-841). An entity taken from `initial_memory_with_schema.json` whose facts were all filtered has no graph node, so its crop cannot seed anything. | medium | M:42; MA:52; MGR:831-841 | Either add such entities as standalone entity nodes linked to their passage, or use `--ontology-filter-mode absolute`. Report the count of candidates without nodes (A15 already asks for the filter loss count). |
| B5 | **Grounding is a topology change, not just seeds.** MG² adds image→entity edges weighted by grounding score (MG2:612-616). M:43 says only "crop matches seed linked entities", and never says whether image–entity edges are added. If they are, each H3 arm changes the graph, and "λ = 0" differs per arm. | medium | M:37-43, M:99; MG2:606-616 | State explicitly whether grounding adds image–entity edges. If it does, run the λ = 0 ablation per H3 arm. |
| B6 | **There is no visual query on MMQA.** MMQA questions are text, so the visual channel is question text through CLIP. M:48 calls that "secondary", and MG² T→V R@1 is 1.8 on E-VQA (RF:212). SigLIP2 truncates at 64 tokens, which compositional MMQA questions can exceed. On MMQA questions usually name entities, so facts pass the gate and the dispatch change (M:55) is mostly irrelevant there. All of H1–H3 on MMQA then rest on a channel the plan itself calls weak. | high | M:48, M:55, M:60, M:148; RF:212 | Per dataset, state the visual query: E-VQA = query image; MMQA = question text via CLIP, or better the attribute span or entity mention. | B8 | **Fusion edge cases and the fact threshold.** `s_visual` can be all zero (division by zero in M:52). `s_text` can be empty, in which case λ is irrelevant after igraph normalises.
